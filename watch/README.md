# Сторож приёмной кампании — юрфак МГУ, платные места

Опрашивает семь источников, сравнивает с прошлым снимком и печатает только
изменения. Пока меняться нечему — молчит.

## Кого стережём

| | |
|---|---|
| Номер в списке подавших | `2055843` |
| Заявление АИС | `152102080150` |
| Код в ведомости ДВИ | `80150` |
| Обществознание ДВИ | 85 баллов (опубликовано 25.07.2026) |

Всё это лежит в `config.py` — при смене данных правится там, `watch.py`
трогать не нужно.

## Чего ждём

1. **Список подавших** — заполнения столбца «Обществознание ДВИ» у 2055843.
   Ждём 85; любое другое число сторож пометит как расхождение.
2. **Конкурсные списки** — переключения страницы с версии 2025 года на 2026,
   затем появления заявления 152102080150: балл, сумма, место, статус.
   Сдвиги места в конкурсе отслеживаются дальше.
3. **Новости юрфака** — объявления о заключении договоров. Заголовки со
   словами из `NEWS_KEYWORDS` («договор», «приглаша», «заключ», …) помечаются
   звёздочкой.
4. **Ведомость ДВИ** — страховка от пересмотра: следим за хешем файла и за
   баллом против кода 80150.
5. **График кампании**, **план приёма**, **проходные прошлых лет** — следим
   за фактом обновления документа.

## Запуск

```bash
pip install requests bs4 lxml pypdf
python3 watch.py              # обычный проход, печатает только изменения
python3 watch.py --report     # напечатать состояние целиком
python3 watch.py --baseline   # перезаписать снимок, ничего не сравнивая
```

Коды возврата: `0` — тихо, `10` — есть изменения, `20` — источник не отвечает
столько раз подряд, что молчание само стало новостью.

Каждые 20 минут по cron:

```
7,27,47 * * * * cd /path/to/Solfeggio-2/watch && python3 watch.py
```

## Почему так устроено

**Поиск по содержимому, а не по вёрстке.** Строка ищется по номеру внутри
любого `<tr>`, шапка берётся из первой строки той же таблицы, раздел — из
ближайшего заголовка выше. Косметические правки сайта парсер переживает;
брать `table.tbody.tr:nth-child(2)` было бы куда хрупче. Абитуриент проходит
по нескольким конкурсам сразу, поэтому строка без указания раздела
бесполезна — раздел пишется всегда.

**Молчание не успокаивает.** Недоступность источника не выдаётся за
«изменений нет»: неудачи считаются подряд, и на третьей сторож объявляет,
что этот источник он больше не покрывает. Худший режим для сторожа — когда
вы думаете, что он следит, а он давно не отвечает.

**Снимок и журнал.** `state/snapshot.json` перезаписывается каждый проход и
хранит текущее состояние. `journal.md` дописывается только при изменениях —
это долговечная история: если контейнер со сторожем пересоздадут, по журналу
видно, что уже случилось и о чём уже сообщали.

## Проверка

```bash
python3 test_watch.py
```

Логика проверяется на HTML, воспроизводящем структуру таблиц cpk: пустой
столбец ДВИ, который потом заполняют; страница 2025 года, которая
переключается на 2026; новость о договорах среди прочих. Тесты стерегут
ровно те переходы, ради которых сторож написан, и не требуют сети.
