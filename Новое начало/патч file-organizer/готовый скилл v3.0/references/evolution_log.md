## Принятые правила

1. Для объекта на рассмотрении верхний контур определяется каналом поступления: переданное инициатором — исходные материалы, собранное или созданное командой — анализ; внутри контуров структура строится по содержанию.
2. Вложение синонимов запрещено.
3. Исходник и рабочий материал имеют разные контуры.
4. Дубли, версии и производные материалы различаются содержательно.
5. Намеренное удаление владельцем создаёт новую текущую базу.
6. Служебные файлы сначала связываются с родителем.
7. Карточка является текущим каталогом, а не журналом действий.
8. После разбора проекта запрашивается управленческое решение о стадии.
9. Перед архивированием проверяется длина предполагаемых целевых путей; имена не сокращаются без подтверждения.
10. Проектный архив строится как `90. Архив\YYYY`; результат хранится в карточке и реестре.
11. Архивный год определяется последним содержательным документом, а его основание фиксируется явно.
12. Условия критерия разрешают рассмотреть подпапку, но она создаётся только при доказанной практической пользе; небольшой комплект исходников по умолчанию хранится плоско.
13. `00. КАРТОЧКА.md` — единственный актуальный управляющий документ проекта; каталог строится автоматически, прежние подробные выводы сохраняются датированными заключениями.
14. Если происхождение определяет маршрут, но не подтверждено, агент фиксирует вторичные признаки и запрашивает решение владельца.
15. Для исторического объекта первый надежно датированный содержательный документ определяет `YYYY-MM` постоянного имени, а последний содержательный документ — год архива; даты копирования Windows не используются.
16. Действующие объекты размещаются в `10. В работе`; имя папки и постоянный ID сохраняются при переходе между стадиями.
17. Для действующего объекта структура строится по функции документов и рабочим процессам; разные оси классификации не смешиваются на одном уровне без обоснования.
18. Приобретение, эксплуатация, экономика, учёт, договорные и инженерные обязательства сначала проверяются по содержимому; диагностический перечень не превращается в набор пустых папок.
19. Нулевой результат поиска не подтверждает отсутствие документов, если есть ошибки извлечения или непрочитанные форматы.
20. Точные копии в тематической и контрагентской ветках не образуют две нормы хранения: выбирается одно каноническое место, а удаление лишнего экземпляра согласуется отдельно.
21. Наследуемый путь является только вторичным признаком; документ заново классифицируется по фактической функции после чтения.
22. Единственный файл хранится прямо в тематическом родителе, если отдельный жизненный цикл, технический интерфейс или неразрывный комплект не доказаны.

30. Перед удалением точного дубля канонический экземпляр проверяется на существование, открытие, целостность и ожидаемую структуру.
31. Контролируемые стадии: `На рассмотрении`, `В работе`, `Архив`; архивные результаты: `Не запущен`, `Завершён`.

34. При параллельном разборе один агент отвечает за один проект, до утверждения работает только на чтение и возвращает обязательный содержательный результат; готовые проекты выдаются владельцу по мере завершения.
35. Для объекта на рассмотрении `01. Исходные материалы` содержит пакет, переданный инициатором или иной стороной проекта; внешние материалы, собранные командой для оценки, относятся к `02. Анализ\<тема>\Источники анализа`.
36. Если в родительском разделе всего 1–3 содержательных файла, они хранятся плоско; подпапки пересматриваются только после фактического накопления, кроме обязательного технического интерфейса или неразрывного многофайлового комплекта.
37. Корневая `00. Входящие` — обязательный постоянный интерфейс каждого проекта: она создаётся автоматически, сохраняется пустой, исключается из очистки пустых папок и проверяется валидатором.

39. Валидатор карточки и автоматического каталога обходит проект через `\\?\`; успешная проверка должна охватывать все файлы независимо от длины Windows-пути.
40. У проекта ровно одна мастер-копия, зафиксированная первым блоком карточки вместе со списком устаревших копий; клон репозитория, распакованный архив, синхронизируемая копия и копия из чата мастером по умолчанию не являются.
41. Перенос между средами выполняется по протоколу: фиксация состава и хешей источника, предупреждение о ловушках среды, перенос без переименования, сверка приёмника, запись нового мастера и только затем отдельное согласование удаления источника.
42. Папка с маркером `.sensitive` не может быть мастер-копией в синхронизируемом облачном пути или внутри клона репозитория с настроенным remote; нарушение сообщается владельцу первым пунктом.
43. Режим проверки расползания работает только на чтение и выдаёт светофор по классам проблем, не предлагая структурных изменений.
