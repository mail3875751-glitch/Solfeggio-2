# Патч file-organizer: v2.9 → v3.0

Повод: сессия 08–10.08.2026. Один проект («Новое начало») за два дня оказался
в четырёх местах одновременно — облачный репозиторий, клон на рабочем столе,
своя папка на рабочем столе, файлы из чата в загрузках. Владелец не смог
ответить на вопрос «где правда», а операция переноса чуть не привела к потере
всей работы (скачивание ветки по умолчанию вместо рабочей).

Скилл этого класса проблем не покрывает: он видит один корень и наводит порядок
внутри него. Ниже — что добавить.

## Что в скилле УЖЕ есть (не дублировать)

- Аудит дублей с SHA-256 внутри одного корня (`scripts/audit_duplicates.ps1`).
- Классификация «точный дубль / содержательный дубль / версия»
  (`references/mode_project_audit.md`).
- Запрет автоудаления: «удаление всегда является отдельным действием»,
  «запрещено автоматически удалять дубли, временные или служебные файлы».
- Проверка канонического экземпляра до удаления дубля.

Просьба «находить дубли, но не удалять без команды» закрыта ещё в v1.1.
Новое — ниже.

---

## 1. Мастер-копия: новый обязательный атрибут проекта

**Проблема.** Скилл знает «каноническое место файла ВНУТРИ проекта», но не знает
«каноническое место САМОГО проекта». Когда копии проекта живут на разных
носителях и в разных средах, отсутствие такого атрибута парализует владельца.

**Вставить в SKILL.md, раздел «Роль», новым пунктом 12:**

> 12. У каждого проекта ровно одна мастер-копия. Её путь фиксируется первым
>     блоком `00. КАРТОЧКА.md` (или README проекта) вместе с поимённым списком
>     известных устаревших копий. Любая найденная копия классифицируется как
>     `мастер`, `архивная копия`, `копия среды` или `мусор`. При обнаружении
>     второй копии без явного мастера — остановиться и спросить владельца,
>     какая копия становится мастером; не выбирать самому по дате.

**Вставить в `references/project_card.md`** обязательный первый блок карточки:

```markdown
## Мастер-копия
- Действующая: <полный путь>
- Устарели (удалить): <путь> — <причина>
- Правило: при двух копиях действующая та, где свежее дата этого файла.
```

## 2. Классы экземпляров, порождённые средами

**Проблема.** Классификация знает дубли и версии, но не знает, ОТКУДА копия
взялась. У копий разных сред разные повадки и разная опасность.

**Вставить в `references/classification_rules.md` таблицей:**

| Класс | Признаки | Обращение |
|---|---|---|
| Клон репозитория | внутри есть `.git` | Не мастер-копия по умолчанию. Проверить, на какой ветке checkout: клон может не содержать рабочих файлов, если они в другой ветке. Не удалять до проверки незапушенных изменений (`git status`) |
| Распакованный архив | имя вида `<репо>-<ветка>`, рядом одноимённый `.zip` | Транзитный объект. После переноса содержимого — мусор. Проверить, что перенесли всё, включая скрытые файлы |
| Копия из браузера или чата | суффикс ` (1)`, ` (2)` в имени; лежит в загрузках | Дубль по определению. Сверить SHA с мастером; при совпадении — мусор, при расхождении — разошедшаяся версия |
| Синхронизируемая копия | путь содержит OneDrive, Dropbox, Google Drive, Яндекс.Диск, iCloud | Не мастер для чувствительных материалов. Отдельно проверить контур конфиденциальности (см. §4) |
| Копия ручного бэкапа | имя папки с датой или «копия», «old», «backup» | Архивная копия. Предложить перенос в `90. Архив` либо удаление; отдельным действием |

**Правило поверх таблицы:** доказательством мастер-копии не являются ни
свежая дата, ни количество файлов, ни расположение на рабочем столе. Мастер —
только тот путь, который записан в карточке проекта.

## 3. Режим «Проверка расползания» — светофор без разбора

**Проблема.** Единственный способ узнать про дубли — заказать полный разбор
папки. Нужен дешёвый регулярный режим: «просто покажи, где плодятся копии
и мусор», без плана реорганизации и без единого изменения.

**Вставить в SKILL.md, таблицу «Режимы», строкой:**

| Проверка расползания, «где плодятся копии», «что тут мусор» | `references/mode_sprawl_check.md` |

**Создать `references/mode_sprawl_check.md`:**

```markdown
# Режим: проверка расползания

Назначение: за один проход показать, где один и тот же материал живёт
в нескольких местах, где версии разошлись и где накопился мусор среды.
Режим только читает. Никаких предложений по реорганизации, никаких перемещений.

## Порядок

1. Уточнить у владельца корни проверки. По умолчанию: рабочий стол, загрузки,
   папка проектов, синхронизируемые папки (если владелец назвал).
2. Запустить `scripts/audit_sprawl.ps1 -Roots <корни>`.
3. Выдать отчёт-светофор:
   - КРАСНЫЙ: один файл в нескольких корнях; чувствительные материалы
     в синхронизируемом или публикуемом пути.
   - ЖЁЛТЫЙ: разошедшиеся версии; клоны репозиториев; распакованные архивы;
     копии «(1)» из браузера; временные файлы.
   - ЗЕЛЁНЫЙ: чисто.
4. По каждому КРАСНОМУ пункту задать ровно один вопрос: какая копия — мастер.
5. Не предлагать структурных изменений. Владелец решает, запускать ли после
   этого полноценный разбор соответствующим режимом.

## Ограничения

Отчёт называет проблему и место, но не совершает действий. Удаление, перенос
и слияние — только отдельными подтверждёнными действиями через обычный workflow.
```

**Добавить скрипт `scripts/audit_sprawl.ps1`** — готов, лежит рядом с этим
файлом. Отличия от `audit_duplicates.ps1`: несколько корней вместо одного;
поиск пересечений МЕЖДУ корнями; распознавание следов сред; проверка
чувствительных папок в синхронизируемых путях; вывод-светофор; поддержка
длинных путей и пропуск служебных каталогов.

## 4. Контур конфиденциальности

**Проблема.** В нашей сессии материалы с характеристиками опознаваемых третьих
лиц и внутрикорпоративными рамками оказались в облачном репозитории. Скилл
следит за целостностью файлов, но не за тем, куда они попадают.

**Вставить в SKILL.md, раздел «Безопасность», после списка запретов:**

> **Контур конфиденциальности.** Папка, помеченная файлом-маркером
> `.sensitive`, не может быть мастер-копией в синхронизируемом облачном пути
> (OneDrive, Dropbox, Google Drive, Яндекс.Диск, iCloud) и не может лежать
> внутри клона репозитория с настроенным remote. При обнаружении такой
> ситуации — сообщить владельцу отдельным КРАСНЫМ пунктом до любых других
> предложений. Признаки чувствительности при отсутствии маркера: персональные
> характеристики третьих лиц, внутренние документы работодателя, финансовые
> данные семьи, медицинские сведения, учётные данные. Предложить владельцу
> поставить маркер, а не решать за него.

## 5. Протокол переноса между средами

**Проблема.** Перенос проекта между компьютерами, из облака на диск, из клона
в обычную папку — операция, где легко потерять всё разом. У скилла нет её
чек-листа, хотя есть детальный протокол архивации.

**Вставить в SKILL.md, раздел Workflow, подразделом после EXECUTE:**

```markdown
### Перенос между средами

Порядок обязателен. Источник не удаляется, пока перенос не проверен.

1. Зафиксировать источник: полный путь, число файлов, суммарный объём,
   SHA-256 каждого файла. Для клона репозитория дополнительно: имя ветки
   и наличие незапушенных изменений.
2. Предупредить владельца о ловушках среды: у репозитория рабочие файлы могут
   лежать не в ветке по умолчанию; облачные папки могут содержать плейсхолдеры
   вместо файлов (файлы «по требованию»); архив может распаковаться во вложенную
   папку.
3. Перенести. Не переименовывать при переносе.
4. Проверить приёмник: число файлов, объём, SHA-256 совпадают; выборочно
   открыть 2–3 документа разных форматов.
5. Записать новый мастер в карточку проекта; перечислить устаревшие копии
   поимённо.
6. Только теперь предложить удаление источника и промежуточных копий —
   отдельным подтверждаемым действием, по одному пункту.
7. Напомнить владельцу, что удаление файлов не удаляет их копии в переписках,
   почте и корзине.
```

## Как применить

1. Файлы этого патча — в `C:\skill-house\file-organizer\` (истина там, не в
   `~/.claude/skills`).
2. Внести правки в `SKILL.md`, поднять версию до 3.0, дописать строку changelog.
3. Положить `audit_sprawl.ps1` в `scripts/`, создать `references/mode_sprawl_check.md`.
4. Прогнать скрипт на своей машине как первый тест:
   `.\audit_sprawl.ps1 -Roots "$env:USERPROFILE\Desktop","$env:USERPROFILE\Downloads"`
   — он же заодно покажет текущее состояние с копиями «Новое начало».
5. Синхронизировать копию скилла в `~/.claude/skills` штатным способом дома.
