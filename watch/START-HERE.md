# Если это новая сессия — начни отсюда

Сторож приёмной кампании готов и лежит в этой же папке. Чтобы поднять его
в свежей сессии, не восстанавливая контекст разговора:

```bash
cd watch
pip install -r requirements.txt
python3 watch.py --report
```

Что должно получиться:

- **Все источники отвечают** — сеть открыта, сторож работает. Если снимка
  ещё нет, первый запуск просто запишет базовый и сравнивать будет не с чем;
  повторный запуск уже начнёт ловить изменения.
- **`НЕДОСТУПЕН (ProxyError)` по всем восьми** — сетевая политика окружения
  всё ещё не пускает домены МГУ. См. «Что нужно от окружения» ниже.

## Что нужно от окружения

Уровень доступа к сети должен быть **Custom**, а в **Allowed domains**
перечислены:

```
msu.ru
*.msu.ru
cpk.msu.ru
www.law.msu.ru
law.msu.ru
priem.law.msu.ru
```

Галочка **«Also include default list of common package managers»** должна
быть включена — иначе отвалятся PyPI (не поставятся зависимости) и прочий
дефолтный список.

Меняется это в селекторе окружения на claude.ai/code: облачная иконка с
именем окружения в строке над полем ввода → навести на окружение → шестерёнка
→ поле **Network access**.

## Как поставить регулярный опрос

В сессии Claude Code — расписание раз в 20 минут, командой вида «проверяй
`watch/watch.py` каждые 20 минут и сообщай только об изменениях». Учти: такое
расписание живёт в памяти сессии и умирает вместе с ней. Чтобы пережить
пересоздание контейнера, нужен постоянный Routine — у него минимальный
интервал час.

На машине с обычным интернетом надёжнее обычный cron:

```
7,27,47 * * * * cd /path/to/Solfeggio-2/watch && python3 watch.py
```

## Что означают коды возврата

| | |
|---|---|
| `0` | тихо, изменений нет |
| `10` | есть изменения — прочитать вывод |
| `20` | источник не отвечает 3+ раза подряд, сторож его больше не покрывает |

Остальное — в `README.md`: кого стережём, чего ждём, почему разбор устроен
именно так.
